## 1. System architecture

Single public entry point is the WAF on `https://localhost:8443`. NGINX + ModSecurity terminate
TLS and route `/` to the Vite frontend and `/api`, `/static`, `/media`, `/django-admin` to Django.
Django settings read the database credentials and `SECRET_KEY` from Vault over AppRole (credentials handed
to it on a shared volume by the one-shot `vault-init`); the OAuth views and the API-key check still read
their values from the environment. Django writes logs to a file that Logstash tails into Elasticsearch/Kibana.

**Reality notes:** with `APP_DEBUG=true` (the `.env.example` default) the frontend and backend run as
**dev servers** (`vite`, `manage.py runserver`); with `APP_DEBUG=false` the backend switches to gunicorn.
The **ELK stack is opt-in** (`docker compose --profile observability`, or `make elk-up`); its TLS certs are
generated by the `elk-cert-init` container. Kibana's `5601` is published to the host, so it is reached
directly, not through the WAF. Logstash tails the backend log file (`./logs/backend.log`).

## 2. Business workflow

Staff pre-generate the night's trips; students book a seat against their home station during the day;
staff see real per-stop demand and reassign buses/routes; a cron archives trips shortly after they run.

```mermaid
flowchart TD
    A["Staff generates trips<br/>BulkGenerateTripsView"] --> B{"Departure hour type?"}
    B -->|"peak: 21, 22, 01"| C["2 trips created:<br/>OCP Route + Coin Blue Route"]
    B -->|"other: 23, 00, 03, 04, 05, 06"| D["1 trip created:<br/>Unified Night Route"]
    C --> E[("Trip rows<br/>route + bus + driver + departure_datetime")]
    D --> E

    S["Student picks home station<br/>opens 'Reserve a seat'"] --> AV["GET /api/v1/trips/available/?station_id=<br/>AvailableTripListView"]
    E --> AV
    AV --> W["Apply booking window (see rules box)"]
    W --> LIST["Returns upcoming, non-archived trips<br/>for that station that still have seats"]

    LIST --> R["POST /api/v1/reservations/<br/>student = request.user (C1 fix — no client user_id)"]
    R --> V1{"Trip archived?"}
    V1 -->|yes| X1["400 LifecycleError"]
    V1 -->|no| V2{"seats_left ≤ 0?"}
    V2 -->|yes| X2["409 CapacityError"]
    V2 -->|no| V3{"Already reserved<br/>this night window?"}
    V3 -->|yes| X3["400 duplicate (one per night)"]
    V3 -->|no| OK["201 Reservation created<br/>DB unique (trip, student)"]

    OK --> CNT["Staff dashboard: real counts per stop / per trip<br/>seats_left = bus.seat_capacity − reservations.count()"]
    CNT --> ALLOC["Staff adjusts bus / route / driver to match demand"]
    ALLOC --> RUN["Trip departs at departure_datetime"]
    RUN --> ARCH["cron archive_trips (every 60s):<br/>departed > 25 min ago AND has reservations<br/>→ sets archived_at"]
    ARCH --> HIST["Trip + its reservations move to history views"]

    subgraph RULES["Booking-window rules — as implemented"]
        direction TB
        N1["now = localtime(now()), TIME_ZONE = Africa/Casablanca"]
        N2["if now.hour < 06 → shift_date = yesterday<br/>else → shift_date = today"]
        N3["window = [ shift_date 21:00  →  (shift_date + 1 day) 06:00 ]"]
        N4["available trip must be: in window<br/>AND departure_datetime ≥ now<br/>AND archived_at is null<br/>AND reservations < bus.seat_capacity"]
        N5["duplicate guard: one reservation per student<br/>per window (get_bus_day_bounds)"]
        N1 --> N2 --> N3 --> N4 --> N5
    end

    W -.->|uses| RULES
```

**The booking window in plain words:** a "bus day" runs **21:00 → 06:00** the next morning. Any time
from 06:00 onward counts toward *tonight's* window, so a student can book tonight's 01:00 bus at 10:00
in the morning — this is the intended rule (it is what M1 fixed the test to match). Before 06:00 you are
still inside *last night's* window. A student may hold **one reservation per window**, capacity is
`bus.seat_capacity`, and a trip is archived ~25 minutes after it departs (only if it had reservations).

## 3. Auth flow

Login is **42 Intra OAuth only**; there is no username/password endpoint. RBAC is enforced per view.
This section reflects the hardened flow (OAuth `state`, server-enforced 2FA, refresh token in an HttpOnly
cookie, access token in memory). *Note: the standalone `auth-flow.mmd` predates these changes; this
section is the current reference.*

```mermaid
sequenceDiagram
    autonumber
    actor U as User (browser)
    participant FE as SPA (Landing / AuthCallback)
    participant BE as Django backend (via WAF :8443)
    participant I42 as 42 Intra API
    participant DB as PostgreSQL

    U->>FE: Click "Login with 42"
    FE->>BE: GET /api/v1/auth/42/login/
    BE-->>FE: { authorization_url } + Set-Cookie fleetmark_oauth_state (HttpOnly, 10 min)
    FE->>I42: redirect to /oauth/authorize?...&state
    I42->>BE: 302 → /api/v1/auth/42/callback/?code&state
    BE->>BE: state == cookie? (constant-time) else → /?auth_error=expired
    BE->>I42: POST /oauth/token, GET /v2/me
    BE->>DB: get_or_create User by login_42 (staff if login == ADMIN_42_LOGIN)
    alt 2FA enabled
        BE-->>FE: 302 → /auth/callback#preauth=<5-min token>&totp=1 (no session)
        U->>FE: 6-digit TOTP code
        FE->>BE: POST /api/v1/auth/2fa/login-verify/ { preauth, code }
        BE-->>FE: { access } + Set-Cookie fleetmark_refresh (HttpOnly, path /api/v1/auth/)
    else 2FA off
        BE-->>FE: 302 → /auth/callback#access&role&login&totp=0 + Set-Cookie fleetmark_refresh
    end
    FE->>FE: keep access token in memory only (never localStorage)
    FE->>BE: GET /api/v1/auth/me/ (Bearer)
    FE->>U: redirect by role → /admin | /passenger | /onboarding | /driver (coming soon)
    Note over FE,BE: On reload the SPA calls POST /auth/token/refresh/ (cookie) for a new access token.<br/>Blocked (is_active=false) users are refused a refresh.
```

**Notes:** the pre-auth token's type (`preauth_2fa`) is not accepted by `JWTAuthentication`, so it cannot
be used as a Bearer token anywhere; only `/2fa/login-verify/` exchanges it. The `X-API-Key` is not a
global default: it is applied only to the read-only station and route endpoints
(`HasAPIKeyOrIsAuthenticated`, see [PUBLIC_API.md](../PUBLIC_API.md)).

## 4. Data model / ERD

Ten domain models plus the custom `User`. All primary keys are UUIDs except the two join tables
(`RouteStation`, `AnnouncementDismissal`), which use auto integer PKs. Operational integrity is enforced
with `PROTECT` on `Trip`'s foreign keys (you cannot delete a bus/route/driver still referenced by a trip)
and `CASCADE` on reservations.

```mermaid

    TRIP ||--o{ RESERVATION : "has (CASCADE)"
```

**Note on `Driver` vs `User`:** `Driver` is a **fleet record** (with its own `username`/`password` and
`default_bus`/`default_routes`), not a login account. The driver-facing portal is not built yet
(`/driver` renders "Coming Soon"), so those driver credentials are not currently used to authenticate.
