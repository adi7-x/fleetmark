## Update log — 2026-07-21 (final hardening pass)

All remaining OPEN items were closed in this pass. Highlights:

- **2FA is now enforced server-side (P0 #2).** A user with TOTP enabled no longer gets a session from
  the OAuth callback — the callback issues a short-lived *pre-auth* token (`PreAuth2FAToken`, distinct
  `token_type`, authenticates nowhere) and the real access/refresh pair is minted only by
  `POST /2fa/login-verify/` after a valid code. New backend tests cover this and prove a normal access
  token can't be replayed as a pre-auth token.
- **Tokens are out of localStorage (P0 #3).** The refresh token now lives in an HttpOnly/Secure/SameSite
  cookie scoped to `/api/v1/auth/`; the access token is held in memory only. Added `restoreSession()`
  (recovers a session from the cookie on load), a real `/logout/` endpoint that clears the cookie
  server-side, and a `ready` gate on `ProtectedRoute` so a reload doesn't flash-redirect.
- **Dependencies clean (P1 #7).** `npm audit` is now **0 vulnerabilities** (was 17); `react-router-dom`
  → 7.18.x, `vite` → 7.3.x. Production build verified.
- **Production servers (P1 #6).** Backend serves via **gunicorn + WhiteNoise** and frontend serves a
  static `vite build` when `APP_DEBUG=false`; dev/eval keeps the dev servers. Both gated so the current
  eval setup is unchanged.
- **Django hardening (P1 #9).** `SECURE_SSL_REDIRECT`, secure cookies, HSTS, nosniff — all added, gated
  on `DEBUG`.
- **ELK now actually starts (P2 #12).** TLS certs are generated by a container-native `elk-cert-init`
  one-shot (openssl, no host `mkcert`); the whole stack is behind an opt-in `observability` compose
  profile (`make elk-up`).
- **Tests (P2 #15/#16).** `apps/reports` went from 0 tests to 8 (and exposed/fixed a latent
  `reporter.username` bug — the field doesn't exist on the custom User model). Frontend test suite stood
  up with Vitest + RTL (11 tests) covering the in-memory token handling and `ProtectedRoute`.
- **Cleanup (P2 #13, P3 #17/#18/#19).** Lockfile-hash-keyed frontend install; unpinned the shared
  node_modules volume; deleted the dead `components/AuthCallback.jsx` + `handleCallback()`; the
  `__import__` timezone hack was already gone.

**Verified this pass:** backend suite = **73 tests, all passing**; frontend suite = **11 tests, all
passing**; `npm audit` = **0 vulnerabilities**; production `vite build` + `gunicorn` boot both verified.

## P0 — Correctness / security, blocks real users

### 1. Reservation IDOR — `user_id` came from the request body · **EDIT · S · ✅ DONE**
- **What:** the create endpoint trusted a client-supplied `user_id`, so any authenticated student could
  book seats in another student's name or exhaust their one-per-night slot.
- **Why it matters:** broken object-level authorization on the single most important action. For a real
  school this is "students booking under each other's identity."
- **File:** [reservations/views.py:44](../fleetmark/backend/apps/reservations/views.py#L44)
- **Fix (applied):** dropped `user_id`; the view now uses `student=request.user` for both the duplicate
  check and the create. Added `test_cannot_reserve_on_behalf_of_another_user`.

### 2. 2FA is not enforced server-side · **ADD · M · ☐ OPEN**
- **What:** the OAuth callback issues a fully valid access+refresh JWT *before* any TOTP check. The
  `totp_required` flag is only honored by the frontend, so a user with 2FA "on" is already logged in.
- **Why it matters:** the 2FA is decorative — it protects nothing. This is also a claimed 42 point that
  isn't real.
- **File:** [users/views.py](../fleetmark/backend/apps/users/views.py) (callback token issuance) + the
  `TOTPVerifyView`.
- **Fix:** if `user.totp_enabled`, issue only a short-lived *pre-auth* token; mint the real access/refresh
  pair only after `POST /2fa/verify/` succeeds. (Queued as **H1**, pending owner approval.)

### 3. Tokens in URL fragment + localStorage · **EDIT · M–L · ☐ OPEN**
- **What:** the callback redirects to `…/auth/callback#access=…&refresh=…`; the SPA stores both in
  `localStorage`. Fragments leak via history/referrer; localStorage is exfiltratable by any XSS (and there
  are live React Router XSS advisories — see item 7). Refresh token lives 7 days.
- **Why it matters:** turns any XSS into week-long account takeover.
- **Files:** [users/views.py](../fleetmark/backend/apps/users/views.py) (redirect),
  [services/api.js:14](../fleetmark/frontend/src/services/api.js#L14),
  [context/AuthContext.jsx](../fleetmark/frontend/src/context/AuthContext.jsx).
- **Fix:** refresh token → HttpOnly/Secure/SameSite cookie; access token in memory only. (Queued as
  **H3**, pending approval — it touches the login flow on both ends.)

### 4. OAuth `state` / login-CSRF · **ADD · M · ✅ DONE**
- **What:** the authorize URL had no `state` and the callback validated nothing — classic OAuth CSRF.
- **File:** [users/views.py](../fleetmark/backend/apps/users/views.py) (login + callback).
- **Fix (applied):** login issues a random `state` in an HttpOnly/Secure/SameSite=Lax cookie and in the
  URL; the callback rejects any mismatch with a constant-time compare. 3 tests added.

## P1 — Required before a real deployment

### 5. `BulkDeleteTripsView` deletes ALL trips unconditionally · **EDIT · S · ☐ OPEN**
- **What:** `Trip.objects.all().delete()` — no filter, no date scope, no confirmation; cascades to every
  reservation.
- **Why it matters:** one staff request destroys all operational data. For a real client this is a
  data-loss footgun that should never exist as-is.
- **File:** [trips/views.py:216](../fleetmark/backend/apps/trips/views.py#L216)
- **Fix:** require an explicit scope (date range or IDs) and a confirmation flag; reject an unscoped
  delete.

### 6. Dev servers shipped as production · **UPDATE · L · ☐ OPEN**
- **What:** frontend runs `vite` (HMR dev server), backend runs `manage.py runserver`. Both print their
  own "do not use in production" warnings.
- **Why it matters:** no static build, HMR websocket exposed, and it makes the Vite dev-server CVEs (item
  7) reachable. Won't survive real load.
- **Files:** [entrypoint.sh:34](../entrypoint.sh#L34),
  [fleetmark/backend/entrypoint.sh](../fleetmark/backend/entrypoint.sh).
- **Fix:** `vite build` served as static files by the WAF/nginx container; gunicorn or uvicorn for Django.
  *Hand to whoever owns deployment.*

### 7. `npm audit` — 9 high-severity vulnerabilities · **UPDATE · M · ☐ OPEN**
- **What:** 17 total (2 low, 6 moderate, 9 high). React Router (7 CVEs incl. RCE via vendored
  turbo-stream, stored/reflected XSS, open redirect, CSRF), Vite (arbitrary file read via dev-server
  WebSocket, `fs.deny` bypass, path traversal), serialize-javascript RCE.
- **Why it matters:** the React Router XSS + Vite file-read are directly reachable given item 6.
- **File:** [fleetmark/frontend/package.json](../fleetmark/frontend/package.json).
- **Fix:** `npm audit fix`; bump `react-router-dom` to a patched 7.x; re-run the suite. Verify the router
  upgrade doesn't break routing.

### 8. "Public API key" gate is a dead default · **EDIT · M · ☐ OPEN**
- **What:** the global default permission is `[HasAPIKey, IsAuthenticated]`, but almost every view sets
  its own `permission_classes`, which drops `HasAPIKey`. The SPA never sends `X-API-Key` either.
- **Why it matters:** the "Public API + API Key" feature protects essentially nothing on the CRUD surface
  (another claimed point that isn't real).
- **Files:** [settings.py:126](../fleetmark/backend/ssbs/settings.py#L126),
  [permissions.py:6](../fleetmark/backend/apps/users/permissions.py#L6).
- **Fix:** decide which endpoints constitute the external API and apply `HasAPIKey` there deliberately;
  stop relying on an overridden global default.

### 9. Django production-hardening settings missing · **ADD · S · ☐ OPEN**
- **What:** `SECURE_SSL_REDIRECT`, `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE`, `SECURE_HSTS_*` unset
  (HSTS is only at nginx); `ALLOWED_HOSTS` defaults to `*`; `DEBUG` is env-toggleable.
- **File:** [settings.py](../fleetmark/backend/ssbs/settings.py).
- **Fix:** add the secure-cookie / SSL-redirect / HSTS settings, gated so local dev stays usable.

## P2 — Robustness and quality

### 10. API key compared with `==` (timing side-channel) · **EDIT · S · ☐ OPEN**
- **File:** [permissions.py:12](../fleetmark/backend/apps/users/permissions.py#L12).
- **Fix:** `hmac.compare_digest(api_key, expected_key)`.

### 11. One-per-night check races across different trips · **EDIT · M · ☐ OPEN**
- **What:** the DB unique constraint + `select_for_update` protect a single trip, but the "already reserved
  this night" check spans trips and is check-then-insert with no cross-trip lock.
- **File:** [reservations/views.py:62](../fleetmark/backend/apps/reservations/views.py#L62).
- **Fix:** enforce at the DB level (per-student-per-window constraint) or lock the student row.

### 12. ELK never starts — `elk/certs/` never generated · **ADD · M · ☐ OPEN**
- **What:** Elasticsearch/Kibana/Logstash mount TLS certs from `elk/certs/`, which does not exist;
  `elk/setup-certificates.sh` is never invoked by compose. Also ELK claims most of the ~3.4 GB free RAM on
  this machine.
- **Why it matters:** the whole observability story (and 2 claimed points) is non-functional. Logging to
  file still works; only the ES/Kibana pipeline is down.
- **Files:** [elk/setup-certificates.sh](../elk/setup-certificates.sh),
  [docker-compose.yml](../docker-compose.yml) (elk services).
- **Fix:** wire cert generation into startup (a one-shot like `vault-init`), document the RAM need, and
  keep ELK on an opt-in compose profile so the core app runs without it.

### 13. Fragile frontend entrypoint dependency check · **EDIT · S · ☐ OPEN**
- **What:** reinstalls only if `node_modules` is absent or `vite` is missing. A stale/partial install
  passes the check — this is exactly what caused the `recharts` crash earlier this session.
- **File:** [entrypoint.sh:25](../entrypoint.sh#L25).
- **Fix:** run `npm ci` keyed on a lockfile hash (store the hash; reinstall when it changes).

### 14. `reports` view 500s on a null role · **EDIT · S · ☐ OPEN**
- **What:** `user.role.upper()` — if `role` is ever `None` (e.g. a GDPR-anonymised user) this throws; also
  inconsistent with the exact-match `'LOGISTICS_STAFF'` used elsewhere.
- **File:** [reports/views.py:15](../fleetmark/backend/apps/reports/views.py#L15).
- **Fix:** compare `getattr(user, 'role', None) == 'LOGISTICS_STAFF'`.

### 15. `apps/reports` has zero tests · **ADD · M · ☐ OPEN**
- **What:** incident reporting — a core student-facing feature — has no test coverage at all.
- **File:** [reports/tests.py](../fleetmark/backend/apps/reports/tests.py) (empty of tests).
- **Fix:** add tests for create/list/permission (student sees own, staff sees all, status update is
  staff-only, null-role path from item 14).

### 16. Frontend has zero tests · **ADD · M–L · ☐ OPEN**
- **What:** no test/spec files anywhere under `fleetmark/frontend/src` — including `ProtectedRoute`, the
  auth context, and the API refresh logic.
- **Fix:** stand up Vitest + React Testing Library; start with `ProtectedRoute`, token refresh, and the
  reservation flow.

## P3 — Hygiene and cleanup

### 17. Dead callback code · **REMOVE · S · ☐ OPEN**
- **What:** [components/AuthCallback.jsx](../fleetmark/frontend/src/components/AuthCallback.jsx) is not
  imported anywhere (the app uses `pages/AuthCallback.jsx`). Its JSON `handleCallback` path
  ([services/api.js:132](../fleetmark/frontend/src/services/api.js#L132)) sends `?code=` with no `state`
  and would now 400 after the OAuth-state fix.
- **Fix:** delete the unused component and the dead `handleCallback` fallback so there's one callback path.

### 18. Leftover `lastproject` node_modules volume · **REMOVE · S · ☐ OPEN**
- **What:** the named volume `ssbs-frontend-node-modules` was first created by an unrelated compose
  project (`lastproject`); reusing it caused the partial-install `recharts` crash. The compose file pins a
  global `name:` for it, so it's shared across projects.
- **Why it matters:** silent, hard-to-diagnose frontend breakage on a fresh clone.
- **Files:** [docker-compose.yml](../docker-compose.yml) (volume def). Volume: `ssbs-frontend-node-modules`.
- **Fix:** `docker volume rm ssbs-frontend-node-modules` and rebuild, and drop the hard `name:` pin so the
  volume is scoped to this project.

### 19. `__import__` hack in GDPR export · **EDIT · S · ☐ OPEN**
- **File:** [users/views.py:274](../fleetmark/backend/apps/users/views.py#L274).
- **Fix:** replace `__import__('django.utils.timezone', …).now()` with a normal top-level
  `from django.utils.timezone import now`.

### 20. `.env.example` was missing · **ADD · S · ✅ DONE**

- **Fix (applied):** created [.env.example](../.env.example) from `docker-compose.yml`,

### 21. README drift · **UPDATE · S · ✅ DONE**

### 22. Failing booking-window test · **EDIT · S · ✅ DONE**
